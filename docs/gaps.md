- **自律レベル / 停止条件 / 予算・利用量上限**: ~~未実装~~ → **Draft only

## §9 セキュリティ/キー管理

- **private base_url SSRF**: 対策済み (2026-10)。`ALLOW_PRIVATE_BASE_URL`
  で web 登録時 + runner 実行時の二重で拒否。DNS rebinding は残存。
- **登録の開放**: GitHub アカウントがあれば誰でも登録できるまま。
  閉じるなら allowlist または validateUserInfo で先着1名化。
- **EXECUTOR_TOKEN のスコープ**: 単一 god-mode トークン。任意 user_ref の
  ジョブ作成を許しているため、漏洩=全キー解決可能。作品単位のペアリング
  (spec 記載の将来案) への移行が本筋。
- **リトライ/増長**: ジョブ試行上限 (8) は実装済み。progress_events 等の
  retention/掃除は未実装。
- **キーの失効 (revoke) セマンティクス**: 削除で代替しているが、作品が
  削除済みキーを参照し続ける時のフォールバック (最新キーに自動切替) は
  ユーザーに見えにくい。削除済みキー参照の明示か、参照の自動クリアが欲しい。
  目安: 小〜中。
- **作品の削除・エクスポート**: spec は明確に要求していないが、アカウント
  削除・作品単位の削除導線は無い。目安: 中。
