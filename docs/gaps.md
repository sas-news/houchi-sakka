## §3.4 実行体・Studio

- **ローカル Runner 形態**: ユーザー固有 Runner の紐付け (ペアリングトークン
  発行、npx 配布 CLI、runner 単位のステータス表示) が無い。現状はサーバー共有
  実行体のみ。キュー滞留検出の警告は入れたが、完全な閲覧モード (全タブの
  書き込み抑止) は「どの Runner か」の概念が無いと作れない。
  目安: 中〜大 (契約: runner 登録・認可、UI、CLI パッケージ)。
- **失敗ジョブの可視化**: `listOpenJobsByWork` は queued/leased のみで、
  failed/cancelled ジョブは API・UI のどこにも出ない。失敗した実行の
  エラー表示と再送導線が欲しい。目安: 小〜中。

## §4.3 コミットメント / 知識管理

- **確定度の3系統** (確定・仮置き・未確定): canon_facts は「正典」のみで
  確定度を持たない。対話で「仮置き」を扱う枠組みが無い。目安: 中。
- **ナレッジトラッキング MVP** (誰が何を知っているか): 未着手。秘密マーク
  付き正典のフィールドも無い (validators の秘密漏洩検査はマーク前提)。
  目安: 大 (§6.4 と一体のデータモデル)。

  コミット) にはなっていない。目安: 中。

## §9 セキュリティ/キー管理

- **キーの失効 (revoke) セマンティクス**: 削除で代替しているが、作品が
  削除済みキーを参照し続ける時のフォールバック (最新キーに自動切替) は
  ユーザーに見えにくい。削除済みキー参照の明示か、参照の自動クリアが欲しい。
  目安: 小〜中。
- **作品の削除・エクスポート**: spec は明確に要求していないが、アカウント
  削除・作品単位の削除導線は無い。目安: 中。
